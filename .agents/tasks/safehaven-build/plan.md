## Critical Next.js 16 / Zod v4 Gotchas

1. **`params` and `searchParams` are Promises** — always `await` them in async server components. In client components use `React.use(params)`.
2. **Route handler signature:** `export async function GET(request: Request, { params }: { params: Promise<{ id: string }> })`
3. **`LayoutProps<'/path'>` and `PageProps<'/path'>`** are globally available (generated by `next dev`/`next build`) — do NOT import them.
4. **`proxy.ts`** is the renamed middleware — exports `proxy` and `config`. Never rename or modify this file.
5. **Tailwind v4 syntax:** `@import "tailwindcss";` and `@theme inline { ... }` — do NOT change the `@import` line or existing font variables in `globals.css`.
6. **`cacheComponents: true`** is set — wrap any per-user data fetching in layouts with its own `<Suspense>` boundary or move it to the page.
7. **Zod v4:** `import { z } from 'zod'` — API is backward-compatible for `.object()`, `.string()`, `.safeParse()`, `.parse()`. `.infer<>` syntax unchanged.
8. **Server Actions** go in `'use server'` functions or dedicated `src/app/actions/` files, never in client components.
9. **Supabase env key name** is `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` (non-standard) — keep as-is.
10. **Never expose service role key** to client. All DB queries go in Server Components or Route Handlers.
11. **`src/app/supabase-check/page.tsx`** — do not overwrite; it confirms the DB connection works.

## Security checklist (verify before merging)

- All database queries are in Server Components or Route Handlers — no client-side Supabase queries
- Every route handler validates session before touching data
- Zod validation on all form inputs
- Service role key is not referenced anywhere in the codebase
- Error messages do not reveal internal details
- Report IDs are never exposed in URLs or API responses
- RLS is active — no `supabase.auth.admin` calls from client context
- Consent is explicit and separate from general terms on the report forms
